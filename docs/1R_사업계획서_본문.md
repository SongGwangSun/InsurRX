## Q1. 문제 인식(problem)

**1) 착안 계기와 해결하려는 문제**

오래전 친구의 딸아이가 "약 봉지를 찍으면 보험금을 받을 수 있는지 알려주면 좋겠다"고 말한 적이 있습니다. 좋은 아이디어라고 생각했지만 당시에는 직장 생활로 실행하지 못했습니다. 이후 아이 셋을 키우며 병원에 갈 때마다 실손보험 청구를 미루다 결국 놓치는 일이 반복되었고, 주변의 직장인 부모들도 같은 경험을 이야기했습니다. 지금은 사진 속 글자를 읽는 AI와 약관을 찾아 읽는 AI가 실제 서비스 수준에 도달해, 그때 포기한 아이디어를 직접 구현할 수 있게 되었습니다.

해결하려는 문제는 **"청구할 만한지, 얼마 나오는지 모른 채 소액 실손보험금을 포기하는 것"**입니다. 소비자는 진료비 몇만 원에 대해 받을 금액이 "몇천 원일 것"이라고 짐작하고 청구를 포기합니다. 그러나 실손보험은 외래·약국 비용을 합산해 공제하는 등 계산 규칙이 복잡하여, 실제로 받을 수 있는 금액을 청구 전에 알 방법이 없습니다.

**2) 목표 고객과 문제의 크기**

목표 고객은 두 집단입니다. 첫째는 **자녀를 둔 맞벌이 가정**입니다. 아이의 소아과·이비인후과 진료가 월 2~3회로 잦고, 진료 1건의 금액이 작으며, 부부 모두 일하느라 청구를 챙길 시간이 부족합니다. 둘째는 **독거노인 등 정보 취약계층**입니다. 병원 이용은 잦지만 약관과 청구 절차를 이해하기 어렵고, 대신 챙겨 줄 가족이 곁에 없어 받을 수 있는 보험금을 놓치기 쉽습니다. 이 밖에 정기적으로 통원하는 만성질환자와 부모님 진료비를 대신 청구하는 자녀도 고객입니다.

한국소비자원이 최근 1년 내 실손보험금을 청구한 1,500명을 조사한 결과, **37.5%가 청구를 포기한 경험**이 있었고, 그 이유로 **"받을 보험금이 소액이어서"가 80.1%**, "보장 대상인지 모호해서"가 13.9%였습니다. 소액 포기 1회의 금액은 약 13,500원, 평균 2.9회였습니다. 즉 포기의 주된 원인은 서류보다 **금액과 보장 여부를 모르는 것**입니다.

**3) 시장 규모와 기존 해결 방식의 한계**

| 구분 | 규모 | 출처 |
|------|------|------|
| 실손보험 보유계약 | 3,622만 건 (2025년 말) | 금융감독원, 2025년 실손의료보험 사업실적(잠정) |
| 연간 지급보험금 (전체 시장) | 약 17조 원 (2025년) | 같은 자료 |
| **1단계** 목표 시장: 연간 미청구 실손보험금 (추정) | 2021년 2,559억 원, 2022년 2,512억 원, 2023년 3,211억 원 (연평균 약 2,760억 원) | 국회 정무위원회 윤창현 의원실, 국민건강보험공단 제출 자료·보험사 통계 분석 (2023.9.6. 보도) |
| **2~3단계** 확장 시장: 숨은보험금 (지급 사유가 생겼으나 찾아가지 않은 보험금) | 약 11조 2천억 원 (중도보험금 8조 4,083억 원, **만기보험금 2조 1,691억 원**, 휴면보험금 6,196억 원). 2025년 말 약 10조 3천억 원 | 금융위원회 보도자료 「숨은보험금 11조 2천억원을 찾아가세요」(2025.6.30.), 2026.7. 발표 |

시장은 단계별로 예측합니다. 1단계는 표준약관으로 계산할 수 있는 실손보험의 미청구액(연평균 약 2,760억 원)을 목표로 합니다. 2~3단계에서 정액형 보험(진단·수술·입원)과 일반 보험의 청구까지 넓히면 금융위원회가 집계한 숨은보험금(약 10~11조 원, 이 가운데 만기보험금만 2조 원 이상)까지 대상이 커집니다. 다만 숨은보험금은 해마다 새로 생기는 금액이 아니라 쌓여 있는 잔액이므로, 2단계 이후의 연간 시장 규모는 비공개 테스트와 설문으로 다시 추정합니다.

기존 해결 방식은 청구를 **접수**하는 데 집중되어 있습니다. 실손24(실손보험 청구 전산화)는 2026년 10월부터 네이버·토스에서도 이용할 수 있게 되었지만, 2026년 9월 28일 기준 연계된 의료기관은 전체 10만 5,643곳 중 5만 340곳(47.7%)이고(금융위원회), 청구 전에 예상 금액을 알려주지 않습니다. 보험사 앱도 청구 접수 후에야 결과를 알 수 있고, 설계사나 콜센터는 소액 건마다 묻기에는 부담이 큽니다. **청구 여부를 결정하는 단계, 곧 "얼마를 왜 받는가"를 알려주는 서비스는 비어 있습니다.**

1R 멘토링을 거치며 목표 범위를 "가입한 모든 보험의 보상 확인"에서 **"실손보험 표준약관 기준 예상 환급금 조회"**로 좁혔습니다. 실손보험은 표준약관으로 상품 구조가 통일되어 있어 보험사별 약관 없이도 계산할 수 있고, 가입자가 가장 많기 때문입니다.

## Q2. 실현 가능성(solution)

**1) 핵심 기능과 문제 해결 방식**

InsurRX는 영수증·처방전 사진 한 장으로 **실손보험 예상 환급금을 청구 전에, 계산식과 근거 조항과 함께** 알려주는 웹 서비스입니다.

① 사용자가 진료비 영수증·처방전·약봉투를 촬영합니다. ② AI가 병원 종별, 급여·비급여 본인부담금, 상병코드, 처방 약품을 읽고, 사용자가 인식 결과를 확인·수정합니다. ③ 금융감독원 감독규정의 **실손의료보험 표준약관**(보험업감독업무시행세칙 [별표15], 2026.5.6. 개정)에서 관련 조항을 찾아 보상 여부와 예상 환급금을 계산합니다. ④ 결과 화면에 "진료비 20,500원 + 약제비 8,000원 − 의원 통원 공제 10,000원 = 예상 환급금 18,500원"처럼 **산정식**과 근거 조항을 보여 주고, 실손24·보험사 앱으로 청구하는 방법과 필요 서류를 안내합니다. 최종 금액은 보험사 심사로 정해진다는 점과, 실제 결과가 다를 때 확인할 점(가입 세대, 비급여, 중복 보장)도 함께 안내합니다.

**2) 개발·구현 방법과 준비 정도**

서비스는 직접 개발했으며, 2026ICT AI 서비스 개발 과정에서 익힌 기술로 구현했습니다. 사진 인식은 GPT-4o Vision, 약관 검색은 표준약관을 조항 단위로 나눠 저장한 벡터 DB(Pinecone), 판단은 GPT-4o가 맡는 RAG 구조입니다. 서버는 FastAPI(Railway), 화면은 GitHub Pages로 운영합니다.

| 구분 | 내용 | 상태 |
|------|------|------|
| 서비스 운영 | 웹 서비스 배포 (song2nes.com), 자동 테스트 123개 통과 | ✅ 완료 |
| 사진 인식 | 영수증·처방전·약봉투 인식, 인식 결과 확인·수정 화면 | ✅ 완료 |
| 표준약관 계산 | 실손 표준약관 기본형·특약1·특약2 조항 검색, 공제 기준 반영, 산정식·근거 조항 표시 | ✅ 완료 |
| 결과 안내 | 추정치 고지, 청구 방법·필요 서류, 차이 발생 시 확인 절차 | ✅ 완료 |
| 개인정보 | 사진 미저장, 민감정보·국외 이전 별도 동의, 개인정보 처리방침, 회원 탈퇴, 가입 시 이메일·이름·비밀번호만 수집 | ✅ 완료 |
| 회원 | 가입·로그인, 기기에 저장된 조회 이력 보기·삭제 | ✅ 완료 |

| 정확도 검증 | 실제 지급 결과와 비교하는 검증 데이터 30~50건 | 🔲 예정 |
| 가입 세대별 계산 | 1~4세대 가입자의 공제·자기부담률을 반영하는 규칙 엔진 | 🔲 예정 |

예시 영수증(의원 외래 20,500원 + 약국 8,000원)으로 실제 AI를 호출해, 표준약관대로 외래·약국을 합산한 뒤 1회 공제한 18,500원이 나오는 것을 확인했습니다. 실제 지급액과 비교한 정확도 검증은 아직 하지 않았으며, 2R에서 진행합니다.

**3) 차별성과 실현 역량**

|------|:---:|:---:|:---:|
| 청구 전 예상 환급금 | ○ | × | × |

InsurRX는 청구 도구와 경쟁하지 않고 그 **앞 단계**를 맡습니다. 실손24의 청구 흐름(보험계약 선택 → 병원·진료일 선택 → 전송)과 자녀·부모 대리 청구 메뉴를 검토해, 조회 결과에서 실손24 연계 병원이면 실손24로, 미연계 병원이면 서류 청구로 바로 이어지도록 안내할 계획입니다. 또한 보험사별 약관을 모으는 대신 감독규정의 표준약관 하나로 모든 보험사의 실손을 계산하므로 약관 확보 비용이 들지 않습니다. 기획부터 개발·배포·운영까지 혼자 직접 해 왔고, 1R 기간 동안 두 차례 멘토링 의견을 서비스 범위 조정과 개인정보 보호 기능으로 실제 서비스에 반영했습니다. 자녀 진료비 청구를 놓쳐 본 당사자로서 목표 고객의 상황을 직접 이해하고 있다는 점도 강점입니다.

## Q3. 성장전략(scale-up)

**1) 수익 구조와 초기 시장 진입 전략**

InsurRX는 소비자, 특히 맞벌이 가정과 독거노인 같은 정보 취약계층이 이미 낸 보험료만큼의 권리를 놓치지 않게 돕는 **ESG(사회적 가치) 사업**입니다. 사회적 가치를 우선하되, 서비스를 계속 운영하려면 운영비는 스스로 벌어야 하므로 원가를 먼저 계산하고 요금을 여러 구분으로 나눠 설계했습니다.

| 단계 | 서비스 | 수익 |
|------|--------|------|
| 1단계 (무료 검증) | 실손 예상 환급금 조회를 누구나 무료로 이용, 사용 후 설문 | 없음 (지원금으로 운영) |
| 2단계 (유료 기능) | 모아 청구, 정밀 조회, 정액형 보험 조회 확대 | 아래 요금 구분 |
| 3단계 (청구 연결) | 손해사정사 협업으로 일반 보험 청구까지 연결 | 협업 수입, 배너 광고 |

| 요금 구분 | 대상 | 내용 | 가격 (설문으로 결정) |
|-----------|------|------|------|
| 기본 조회 | 누구나 | 영수증 1건의 예상 환급금·근거 조항·청구 안내 | 무료 |
| 취약계층 | 독거노인·기초생활수급자 등 | 모든 기능 | 무료 |
| 모아 청구 | 진료가 잦은 가정 | 휴대폰에 모아 둔 여러 영수증을 합산해 한 번에 청구할 금액과 서류 정리 | 합산 예상 환급금이 기준(예: 3만 원) 이상일 때만 1회 정액(예: 1,000원) |
| 정밀 조회 | 가입 세대·특약을 아는 사용자 | 세대·특약을 반영한 계산 | 건당 500~1,000원 |
| B2B | 보험 설계사·GA | 상담용 조회 API | 호출 건당 |
| 광고 | 보험사 | 배너 링크 (조회 결과에 개입하지 않음) | 노출·클릭 기준 |

| 원가 (가정) | 1년차 (조회 3만 건) | 3년차 (조회 40만 건) | 산출 근거 |
|------|------:|------:|------|
| AI 사용료 (변동비) | 105만 원 | 1,400만 원 | 조회 1건 약 35원 (사진 인식 약 1원 + 분석 약 30~35원) |
| 서버·DB·벡터 DB·도메인 | 120만 원 | 240만 원 | 월 10만 원 → 20만 원 |
| 보안 취약점 점검 | 300만 원 | 300만 원 | 연 1회 외주 |
| 법률·개인정보 자문 | 100만 원 | 200만 원 | 정기 자문 |
| **연 운영비 합계** | **625만 원** | **2,140만 원** | 대표자 인건비 제외 |
| **조회 1건당 총원가** | **약 208원** | **약 54원** | 합계 ÷ 조회 건수 |

조회가 늘수록 고정비가 나뉘어 건당 원가는 약 208원에서 약 54원으로 내려갑니다. 1년차 운영비는 지원금으로 충당하고, 3년차에는 모아 청구 1만 건(1,000만 원)과 정밀 조회 1만 건(건당 700원, 700만 원)에 B2B·광고 수입을 더해 운영비를 충당하는 것이 목표입니다. 보험금에서 일정 비율을 떼는 방식은 청구 대행으로 해석될 수 있어 쓰지 않고, 모아 청구도 금액과 관계없는 정액으로 받습니다. 유료화는 정확도 목표(판정 일치율 85%, 금액 오차 중앙값 10%)를 달성한 뒤에만 시작합니다.

초기에는 **회원 수 확보를 가장 먼저** 합니다. 회원 규모가 커야 보험사와 제휴·광고를 협의할 때 대등하게 이야기할 수 있기 때문입니다. 맞벌이 가정은 지역 맘카페·육아 커뮤니티와 지인 네트워크에서, 독거노인 등 취약계층은 노인복지관·주민센터와 협력해 사회복지사가 대신 조회해 주는 방식으로 만납니다. 회원 가입 없이 사진 한 장으로 바로 조회되므로 첫 사용 장벽이 낮고, 실손24·보험사 앱 같은 기존 청구 경로로 안내하므로 사용자가 청구 방법을 바꿀 필요도 없습니다.

무료 단계에서도 법적 위험은 미리 관리합니다. 계산 기준은 감독규정의 표준약관으로 공개하고, 진료·처방 정보는 민감정보로 보아 별도 동의를 받으며, 처리 항목과 보관 기간을 개인정보 처리방침에 밝혀 두었습니다. 가입 때 이메일·이름·비밀번호 외에는 받지 않고, 사진과 조회 결과는 서버에 저장하지 않습니다. 조회 기록과 사진 축소본은 사용자 휴대폰에만 저장되어 **서버에는 진료 정보가 남지 않습니다.** InsurRX는 금액을 추정해 알려주는 정보 제공까지만 하고, 3단계의 청구 진행은 손해사정사를 고용하거나 협업해 수행합니다. 보험사 광고는 조회 결과에 개입하지 않는 배너 링크로만 싣습니다.

## Q4. 향후 발전방안(development)

**1) 중장기 발전 방향과 목표**

중장기 목표는 InsurRX를 **"청구 전에 확인하는 보험금 계산 기준"**으로 만드는 것입니다. 현재는 현행 실손 표준약관 기준의 추정치를 보여 주는 단계입니다. 앞으로 실제 지급 결과와 비교한 검증 데이터를 쌓아, 금액이 얼마나 정확한지를 숫자로 공개할 수 있는 서비스로 발전시킵니다. 정확도가 곧 상품이므로, 검증 데이터가 쌓일수록 대형 플랫폼이 쉽게 따라 하기 어려운 경쟁력이 됩니다.

3년 안의 목표는 누적 가입자 5만 명, 연간 조회 40만 건입니다(가정, 1인당 연 8건). 조회 1건의 평균 예상 환급금을 소액 포기 금액(약 13,500원)으로 잡으면, 사용자들이 청구 전에 확인하는 환급금은 연 약 54억 원으로 연간 미청구 실손보험금(연평균 약 2,760억 원)의 약 2%입니다. 이 수치는 비공개 테스트와 설문 결과로 다시 산정합니다.

정확도를 높이려면 사용자가 실제로 받은 금액을 알려 주는 데이터가 필요합니다. 그러나 이 데이터는 개인정보이므로, **정확도 검증과 보안 점검을 먼저 마친 뒤에만** 별도 동의를 받아 모읍니다. 모을 때도 금액과 판정 결과만 남겨 개인을 알아볼 수 없게 하고, 이렇게 고친 계산 규칙이 다시 정확도를 높여 사용자를 늘리는 선순환을 만듭니다.

**2) 제품·서비스 고도화 계획**

| 단계 | 고도화 내용 | 효과 |
|------|-------------|------|
| 계산 정확도 | AI는 보장 여부·급여/비급여 구분만 판단하고, 금액은 가입 세대별 규칙 엔진이 계산 | 같은 입력이면 항상 같은 금액, 1~5세대 모두 대응 |
| 모아 청구 | 휴대폰에 쌓인 영수증 합산, 청구 기한(3년) 알림 | 소액을 모아 한 번에 청구, 반복 사용 |
| 취약계층 화면 | 큰 글씨 화면, 보호자·사회복지사 대리 조회 | 독거노인 등도 이용 |
| 가족 단위 | 자녀·부모님 영수증을 한 기기에서 조회 | 목표 고객의 실제 사용 방식에 맞춤 |
| 제공 채널 | 웹에 이어 카카오톡 챗봇 재개 (구현 완료, 현재 보류) | 앱 설치 없이 사용 |

**3) 고객·시장 확대 방향**

맞벌이 가정과 독거노인 등 취약계층에서 출발해, 정기 통원하는 만성질환자와 부모님 진료비를 대신 청구하는 자녀로 넓힙니다. 이후 보험 설계사·GA에 상담 도구(API)로 제공하고, 병원·약국 창구에서 영수증을 받는 시점에 예상 환급금을 안내하는 제휴로 확장합니다. 실손보험에서 정확도를 검증한 뒤에는 정액형 보험(진단·수술·입원 특약)으로 넓혀, 실손보험 금액 조회에서 일반 보험의 청구까지 지원하는 서비스로 키웁니다. 어느 단계에서든 보험 상품을 추천하거나 판매하지 않고, 보험사 광고도 조회 결과에 개입하지 않는 배너 링크로만 실어, 이미 가입한 보험에서 받을 몫을 놓치지 않게 돕는 중립적인 위치를 지킵니다.

**4) 추가로 필요한 자원과 확보 방향**

| 자원 | 필요한 이유 | 확보 방향 |
|------|-------------|-----------|
