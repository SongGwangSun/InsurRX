## 2. 문제 정의와 시장 규모

### 2-1. 시장 현황 — 실손보험

| 지표 | 수치 | 출처 |
|------|------|------|
| 실손보험 보유계약 | **3,622만 건** (2025년 말, 전년 대비 +0.7%) | 금융감독원, 2025년 실손의료보험 사업실적(잠정), 2026-06 [1] |
| 연간 지급보험금 | **약 17조 원** (2025년, 전년 대비 +11.4%) | 같은 자료 [1] |
| 연간 보험료수익 | 약 18조 원 | 같은 자료 [1] |
| 미청구 실손보험금 추정 | **2021년 2,599억 원, 2022년 2,512억 원** (연평균 약 2,500억 원) | 국회 정무위 윤창현 의원실, 건강보험공단·보험사 통계 분석, 2023-09 보도 [2] |

> v1.1의 "연간 미청구 보험금 2조 원 이상"은 출처를 확인하지 못해 삭제했습니다.

### 2-2. 왜 청구하지 않는가 — 공개 설문

한국소비자원이 최근 1년 안에 실손보험금을 청구한 1,500명을 조사한 결과입니다(2024-08 발표) [3].

| 항목 | 결과 |
|------|------|
| 청구를 포기한 경험이 있음 | **37.5%** (562명) |
| 포기 이유 — 받을 보험금이 소액이어서 | **80.1%** |
| 포기 이유 — 귀찮거나 바빠서 | 35.9% |
| 포기 이유 — **보장 대상인지 모호해서** | 13.9% |
| 포기 이유 — 보험료 할증이 걱정돼서 | 11.4% |
| 소액 포기자의 회당 포기 금액 / 평균 포기 횟수 | 약 **13,500원** / 2.9회 |

이 결과에서 InsurRX가 겨냥하는 지점은 두 가지입니다.

1. **"소액이라서"** — 사용자는 실제 금액을 모른 채 "얼마 안 될 것"이라고 짐작해 포기합니다. 예상 환급금을 먼저 보여 주면 짐작 대신 숫자로 판단할 수 있습니다.
2. **"보장 대상인지 모호해서"** — 표준약관 조항 원문을 근거로 보장·비보장 이유를 보여 줍니다.

> 주의: 이 설문은 **이미 청구해 본 사람**이 대상이라 전체 가입자의 포기율과 다를 수 있습니다. 자체 설문(7-3)으로 보완합니다.

### 2-3. 기존 방식의 한계

| 기존 방법 | 문제점 |
|-----------|--------|
| 실손24 (청구 전산화) | 청구 전에 "얼마 나오는지" 알려주지 않음. 의원·약국 연계율 26.2% (2026-04 기준) [4] |
| 보험사 앱 | 청구 접수 중심. 예상 금액·근거 조항 안내 없음 |
| 콜센터·설계사 | 연락 부담, 응답 지연 |
| 약관 직접 확인 | 실손 표준약관만 수십 쪽, 공제 규칙이 세대·급여/비급여·병원 종별로 다름 |

### 2-4. 시장 규모 산정 (실손 중심)

```
TAM  실손보험 연간 지급보험금        약 17조 원      (금감원 2025 [1])
 └ SAM  연간 미청구 실손보험금        약 2,500억 원   (의원실 추정 2021~22 [2])
     └ SOM  InsurRX가 3년 안에 조회로 연결할 금액   ← 가정 기반 (아래)
```

**SOM 산정 (가정)** — 금액이 아니라 **조회 건수**를 먼저 추정하고, 건수에 단가를 곱합니다.

| 항목 | 1년차 | 3년차 | 근거 |
|------|------:|------:|------|
| 누적 가입자 | 5,000명 | 50,000명 | **가정**. Waitlist·CBT 결과로 수정 |
| 1인당 연 조회 건수 | 6건 | 8건 | **가정**. 페르소나 월 2~3회 진료 중 일부 조회. 7-3 설문 문항 Q3으로 검증 |
| 연간 조회 건수 | 3만 건 | 40만 건 | 위 두 값의 곱 |
| 조회 1건의 평균 예상 환급금 | 13,500원 | 13,500원 | 소비자원 설문의 회당 소액 포기 금액 [3]을 대리값으로 사용 |
| 조회로 확인된 환급금 합계 | 약 4억 원 | 약 54억 원 | 연간 조회 건수 × 평균 환급금. 3년차는 SAM(2,500억 원)의 약 2% |

> 위 표는 사용자에게 돌아가는 돈의 규모입니다. InsurRX의 매출은 8장의 수익 모델에 따라 이 중 일부가 아니라 **조회 건수 × 건당 단가**로 계산합니다.

## 3. 솔루션

### InsurRX의 접근 방식

```
영수증·처방전 사진 1장
        ↓
GPT-4o Vision OCR — 병원 종별, 급여/비급여 본인부담금, 상병코드, 처방 약품
        ↓
사용자가 인식 결과 확인·수정
        ↓
Pinecone 표준약관 검색 (보험업감독업무시행세칙 [별표15], 실손 2026.5.6. 개정)
        ↓
GPT-4o 보상 판단 — 표준약관 공제 기준을 지시문에 명시
        ↓
보상 가능 여부 + 예상 환급금 + 산정식 + 근거 조항 원문 + 청구 방법 안내
```

### 핵심 차별점 요약 (상세는 9장)

| 항목 | InsurRX | 기존 서비스 |
|------|---------|------------|
| 청구 전 금액 | 예상 환급금과 산정식(본인부담금 − 공제액) | 청구 후 결과로만 확인 |
| 근거 | 표준약관 조항 원문 인용 | 결과만 또는 없음 |
| 대상 병원 | 사진이 있으면 어느 의원·약국이든 | 실손24는 연계된 기관만 (의원·약국 26.2%) |
| 약관 확보 | 표준약관 1종으로 전 보험사 실손 공통 계산 | 보험사별 약관 필요 |

## 4. 핵심 기능

### 4-1. Vision OCR ✅

- **엔진**: GPT-4o Vision (gpt-4o-mini)
- **인식 대상**: 진료비 영수증, 처방전, 약품 봉투
- **추출 항목**: 병원명·종별, 진료과, 상병코드(ICD), 진료일, 급여·비급여 본인부담금, 약품명·일수
- **지원 포맷**: JPEG, PNG, WEBP, HEIC, PDF
- **2단계 파싱**: 정규식 1차 추출 → 누락 시 GPT-4o-mini 보완
- 업로드 이미지는 OCR 후 서버에 저장하지 않습니다.

### 4-2. 표준약관 RAG 보상 분석 ✅ (2026-10-26 전환)

- **약관 데이터**: 보험업감독업무시행세칙 [별표15] 표준약관 PDF에서 조항 단위로 추출 (`scripts/build_standard_terms.py`)

| 약관 | 개정 | 조각 수 |
|------|------|--------:|
| 실손의료보험 기본형 (급여) | 2026-05-06 | 66 |
| 특별약관1 (중증 비급여) | 2026-05-06 | 26 |
| 특별약관2 (비중증 비급여) | 2026-05-06 | 27 |

- **Vector DB**: Pinecone `standard-terms` 네임스페이스. **실손 약관 3종(119개 조각)만** 검색하도록 거른 뒤, 상위 15건에서 조항당 2건까지만 남겨 6건을 LLM에 전달합니다. 질병·상해 표준약관(50개)은 2026-10-28부터 검색하지 않습니다.
- **공제 기준 명시**: 표의 형태라 검색이 잘 안 되는 보상 금액 조항은 약관 원문에서 확인해 지시문에 직접 넣었습니다.
  - 급여 통원: 외래와 처방조제를 1회로 합산 후 공제. 의원·병원 max(1만 원, 20%), 종합·상급종합 max(2만 원, 20%)
  - 특약1 통원: max(3만 원, 30%) / 특약2 통원: max(5만 원, 50%)
- **출력**: 보상 가능 여부, 예상 환급금, 계산 내역, 근거 조항 원문, AI 신뢰도, 추정치 고지
- **추적 정보**: 결과마다 모델명, 프롬프트 버전, 처리 시간, 채널 기록
- **v1.2 범위 정리 ✅ (2026-10-28)**: 실손 집중 방침에 따라 질병·상해 표준약관을 검색 대상에서 뺐고, 화면 용어를 "보상 분석" → "**예상 환급금 조회**"로 통일했습니다.

## 8. 비즈니스 모델

### 8-1. 원칙

- 조회 정확도(14장 지표)가 목표에 도달하기 전에는 유료화하지 않습니다.
- **보험금에서 일정 비율을 떼는 방식은 쓰지 않습니다.** 사정·청구 대행 보수로 볼 여지가 있습니다 (8-4).

### 8-2. 건당 원가 — 조회 1건에 드는 비용

조회 1건 = OCR 1회 + 임베딩 1회 + 분석 1회.

| 구성 | 산식 | 1건 비용 (추정) |
|------|------|----------------:|
| OCR (gpt-4o-mini Vision) | 이미지 + 출력 약 3천 토큰 | 약 1원 |
| 질의 임베딩 | 수백 토큰 | 0.1원 미만 |
| 분석 (gpt-4o) | 입력 약 6천 토큰(지시문+약관 6조각+영수증), 출력 약 800 토큰 | 약 30~35원 |
| Pinecone·서버 | 월 고정비 ÷ 조회 수 | 사용량에 따라 변동 |
| **합계 (변동비)** | | **약 35원/건** |

> 토큰 수와 단가는 **추정**입니다 (OpenAI 공개 단가 기준, 환율 1,400원 가정). 분석 결과에 토큰 사용량을 기록해 실측값으로 바꿉니다 (🔲). 3년차 40만 건 기준 변동비는 연 약 1,400만 원입니다.

### 8-3. 수익 모델 후보 — 조회·청구 건수 기준

| 안 | 내용 | 과금 기준 | 법적 위험 | 판단 |
|----|------|-----------|-----------|------|
| **A. 건당 정밀 조회** | 무료 조회는 현행 기준 추정. 유료는 가입 세대·특약 반영 정밀 계산 + 청구 서류 체크리스트 | 조회 1건당 (예: 500~1,000원, 7-3 Q8로 결정) | 낮음 — 정보 제공 | **1순위**. 원가 35원 대비 마진 확보 |
| **B. 월 구독** | 무제한 조회, 가족 영수증, 연간 리포트 | 월정액 | 낮음 | 연 조회 건수(Q9)가 많을 때만 |
| **C. B2B 조회 API** | 설계사·GA 상담 도구 | API 호출 건당 | 낮음 | 2순위. 설계사 인터뷰 후 |
| D. 청구 성사 수수료 | 청구 완료 건당 또는 환급금의 일정 비율 | 청구 건당 | **높음** — 손해사정·청구 대행 해석 가능 | 법률 검토 전 **채택하지 않음** |

**매출 시나리오 (가정)** — 3년차 연 40만 건 조회 중 유료 정밀 조회 전환 10%, 건당 700원 → 연 2,800만 원. 이 규모로는 B2C 단독으로 부족하므로, 판정 일치율 데이터를 근거로 C안(B2B)을 함께 추진합니다.

### 8-4. 손해사정과의 경계

### 9-2. 차별점 정리

1. **"얼마 받는지"를 청구 전에, 산정식으로** — 실손24와 보험사 앱은 청구를 접수하는 도구입니다. InsurRX는 청구 **여부를 결정하는** 단계를 맡습니다. 소액 포기 이유 1위(80.1%)가 바로 이 단계에서 생깁니다.
2. **근거가 공개된 계산** — 금액마다 표준약관 조항과 공제 기준을 함께 보여 줍니다. 사용자가 보험사 결과와 직접 비교할 수 있고, 차이가 나면 13-4 절차로 안내합니다.
3. **약관 확보 비용이 없음** — 보험사·상품별 약관 대신 감독규정의 표준약관 1종으로 모든 보험사 실손을 계산합니다. 경쟁사가 보험사 제휴로 해결하는 문제를 공개 규정으로 해결합니다.
4. **실손24와 경쟁하지 않고 보완** — 청구는 실손24·보험사 앱으로 보냅니다. 실손24 미연계 의원·약국(약 74%)의 영수증도 사진으로 조회할 수 있습니다.

## 13. 예상 금액 산정 근거와 차이 발생 시 안내

### 13-1. 현재 산정 방식과 한계

| 항목 | 현재 (v1.2) | 한계 |
|------|-------------|------|
| 약관 | 실손 표준약관(2026.5.6. 개정, 5세대) | 1~4세대 가입자는 공제·자기부담률이 다름 |
| 공제 규칙 | 표준약관 원문에서 확인한 기준을 지시문에 명시 (4-2) | 계산은 여전히 LLM이 수행 |
| 계산 내역 | 항목별 금액 | 항목 이름이 매번 다를 수 있음 |
| 신뢰도 | LLM이 매긴 값 | 실제 정확도로 보정되지 않음 |
| 추적성 | 모델·프롬프트 버전·처리 시간 저장 | 약관 데이터 버전은 미기록 |

검증 예: 의원 외래 20,500원 + 약국 8,000원 → 1회 합산 후 1만 원 공제 → **18,500원** (실제 LLM 호출, 2026-10-26). v1.1까지의 지시문("의원 1만 원, 약국 8천 원" 각각 공제)은 현행 약관과 달라 수정했습니다.

### 13-2. 사용자 고지 (현재 화면 문구)

> ⚠️ 이 금액은 현행 실손의료보험 **표준약관**(2026.5.6. 개정)과 영수증을 바탕으로 AI가 계산한 **추정치**입니다. 최종 지급 여부와 금액은 보험사 심사로 결정되며, 가입 시기(1~5세대)와 특별약관 가입 여부에 따라 달라질 수 있습니다.

### 13-3. 산정 방식 개선 — 판정과 계산의 분리

```

[개선]  영수증 + 표준약관 ──▶ LLM ──▶ 보상 여부 + 급여/비급여 구분 + 적용 조항
                                           │
        가입 세대·병원 종별 ──▶ 규칙 엔진 ──▶ 금액 + 산정식
```

- 같은 입력이면 항상 같은 금액이 나옵니다.
- 가입 세대를 모르면 세대별 금액 **범위**로 표시합니다 (설문 Q1로 세대 인지율 확인).

### 13-4. 실제 결과와 차이가 날 때의 안내 절차

| 단계 | 내용 |
|------|------|
| ① 차이 원인 확인 | 가입 세대별 공제액·자기부담률 / 비급여 포함 여부 / 중복 보장(비례 보상) / 서류 누락 |
| ② 보험사 재심사 요청 | 지급 산출 내역 요청, 진료비 세부내역서 등 보완 후 재청구 |
| ③ 분쟁조정 | 금융감독원 ☎1332 / e-금융민원센터. 청구권 소멸시효 3년 안내 |
| ④ 서비스 개선 (🔲) | 사용자가 입력한 실제 지급 결과로 규칙·지시문 개선 |

## 14. 사용 반응 지표와 검증 계획

### 14-1. CBT 핵심 지표

| 지표 | 정의 | 목표 (제안) |
|------|------|-------------|
| OCR 성공률 | 인식 성공 / 업로드 | ≥ 90% |
| 조회 전환율 | 결과 조회 / 인식 성공 | ≥ 60% |
| 응답 시간 P90 | 업로드~결과 | 실측 후 설정 |
| 판정 일치율 | 청구 가능 판정 = 실제 지급 여부 | ≥ 85% |
| 금액 오차율 | \|예상 − 실제\| / 실제 | 중앙값 ≤ 10% |
| 실제 청구율 | "청구했어요" 응답 / 청구 가능 판정 | ≥ 50% |
| 재사용률 | 30일 내 2회 이상 조회 | ≥ 40% |
| 건당 원가 | 토큰 사용량 × 단가 | 실측 (8-2 추정 35원과 비교) |
